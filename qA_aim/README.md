# A 题：装甲板识别与运动预测（qA_aim）—— 一体化自瞄软件

> 基于开源视觉框架 [rm_vision](https://github.com/chenjunnn/rm_vision)（算法子模块
> [rm_auto_aim](https://github.com/chenjunnn/rm_auto_aim)）的装甲板检测 / PnP / 跟踪算法，
> 将其 ROS2/C++ 脚本移植为**纯 OpenCV-Python 视频处理模式**，并整合为**单一入口的自瞄软件
> `auto_aim.py`**：可对 MP4 视频逐帧完成"识别 → 位姿解算 → 卡尔曼滤波 → 0.25s 预测 →
> 云台瞄准角输出"的完整自瞄流水线，提供交互式 GUI 与批量处理两种工作方式。

## 〇、自瞄软件总览

### 0.1 软件架构（与真实自瞄系统的对应关系）

```
                          auto_aim.py (统一入口)
┌──────────────┬──────────────────────────────────────────────────────────┐
│ 交互层       │  gui 模式: 实时回放 + 滑动条调参 + HUD + 截图/录像        │
│              │  demo 模式: 无人值守整段处理, 输出演示视频 + 瞄准角 CSV   │
│              │  批量模式: detect / predict / gyro / qr (对应原脚本)      │
├──────────────┼──────────────────────────────────────────────────────────┤
│ 感知层       │  src/detector.py    装甲板检测 (灯条提取+配对)  [检测]    │
│              │  src/pnp_solver.py  PnP 位姿解算 (x,y,z,yaw)    [测距]    │
├──────────────┼──────────────────────────────────────────────────────────┤
│ 决策层       │  src/kalman.py      CV/CA 卡尔曼滤波             [跟踪]    │
│              │  AimPipeline        目标关联 + 状态机 + 预测     [预测]    │
│              │  src/gyro.py        小陀螺车体中心/角速度估计    [特情]    │
├──────────────┼──────────────────────────────────────────────────────────┤
│ 执行层       │  AimPipeline.draw   预测点投影 + 瞄准角(yaw/pitch) [瞄准] │
│              │  HUD 俯视轨迹/滞后误差自检                        [自检]   │
├──────────────┼──────────────────────────────────────────────────────────┤
│ 输出层       │  detections_*.csv / pred_*.csv / aim_*.csv / 识别视频 /   │
│              │  位置曲线 / 俯视轨迹 / 预测对比 / Q·R 分析图              │
└──────────────┴──────────────────────────────────────────────────────────┘
```

### 0.2 自瞄流水线数据流

```
视频帧 ──► 颜色差分二值化 ──► 灯条提取(几何过滤+断裂合并) ──► 灯条配对(小/大装甲板)
   ──► PnP 位姿 (x,y,z,yaw) ──► 深度一致性检验 ──► 目标关联(位置+yaw 双门限)
   ──► 卡尔曼滤波(速度钳制/丢帧重初始化) ──► 前推 0.25s 预测位置
   ──► 瞄准角: yaw_g = atan2(x, z), pitch_g = atan2(-y, √(x²+z²))
   ──► 画面叠加(装甲板框/预测十字线/HUD 俯视轨迹) + CSV + 滞后误差自检
```

### 0.3 软件模块职责

| 模块 | 文件 | 职责 |
|---|---|---|
| 统一入口 | `auto_aim.py` | 6 种模式（gui/demo/detect/predict/gyro/qr），一条命令跑通全流程 |
| 自瞄流水线 | `auto_aim.py::AimPipeline` | 逐帧 检测→PnP→关联→KF→预测→瞄准角，供 GUI 与 demo 复用 |
| 装甲板检测 | `src/detector.py` | detector.cpp 移植 + 颜色差分阈值 + 灯条分段合并 |
| 位姿解算 | `src/pnp_solver.py` | solvePnP(IPPE)，小/大装甲板模型点，yaw 定义 |
| 卡尔曼滤波 | `src/kalman.py` | CV/CA 模型，Q/R 参数化，多步前推预测 |
| 小陀螺估计 | `src/gyro.py` | yaw 锯齿波分段斜率 → ω；位置中位数 → 车体中心 |
| 批量识别 | `run_detect.py` | 逐帧识别 → detections CSV + 可视化视频 |
| 运动预测 | `run_predict.py` | KF + 0.25s 预测 → pred CSV + 曲线 + 误差统计 |
| 调参工具 | `threshold_tuner.py` | 滑动条实时调阈值 + 二值图对照 |
| 参数分析 | `qr_analysis.py` | Q/R 网格扫描 + CV/CA 对比 + 配图 |

### 0.5 使用说明

**方式一：双击启动菜单** —— 双击 `启动自瞄软件.bat`，按数字选择：

|---|---|
| 1~4 | 交互式自瞄演示（远距离平移 / 中距离陀螺 / 近距离陀螺 / 蓝色装甲板仅识别） |

**方式二：拖拽处理** —— 把任意 mp4 视频文件**拖到 `拖拽视频到此处理.bat` 图标上**，

然后选择：`1` 交互式 GUI / `2` 无人值守处理 / `3` 仅批量识别。

**方式三：命令行** —— 见 0.4，先 `cd` 到 `qA_aim` 目录，中文路径务必加引号；
建议先执行 `set PYTHONIOENCODING=utf-8` 避免中文乱码。

**GUI 按键表**：

| 按键 | 功能 |
|---|---|
| 空格 | 播放 / 暂停 |
| n / p | 下一帧 / 上一帧 |
| s | 保存截图 `auto_aim_screenshot.png` |
| r | 开始 / 停止录像 `auto_aim_record.mp4` |
| ESC / q | 退出 |

**GUI 滑动条**（实时生效）：`dom_thres` 颜色差分阈值、`min_area` 灯条最小面积、
`q_acc x10` 卡尔曼过程噪声 Q、`r_xyz x100` 观测噪声 R、`pred_ms` 预测时长（默认 250 ms）、
`speed` 播放速度（跳帧倍数）、`view` 标注图/二值图切换、`frame` 跳转帧。

**画面元素**：绿框 = 装甲板 + 四关键点（lt/lb/rb/rt）；黄十字 = 0.25 s 预测瞄准点；
右上角 HUD = 俯视轨迹（绿点=历史、红叉=预测）、跟踪状态机、观测/滤波/预测位置、
**云台瞄准角 yaw/pitch**、滞后误差自检。

**输出位置**：`detections_*.csv` / `pred_*.csv` / `aim_*.csv` / `qr_analysis.csv`
在 `qA_aim\` 目录；全部曲线图与识别视频在 `qA_aim\figures\` 目录。

**常见问题**：① 中文乱码 → 命令行先执行 `chcp 65001` + `set PYTHONIOENCODING=utf-8`

③ 换电脑运行 → 修改 bat 中 `PY`（Python 路径）与数据路径，环境只需
`pip install opencv-python numpy matplotlib`。

## 三、方案设计与依据

### 3.1 由 rm_vision 到视频模式的移植

| rm_vision 源文件 (C++/ROS2) | 本项目移植 (Python/OpenCV) | 改动 |
|---|---|---|
| `armor_detector/src/detector.cpp` | `src/detector.py::Detector` | 算法结构完全一致 |
| `armor_detector/include/armor_detector/armor.hpp` | `src/armor_types.py` (Light/Armor) | 灯条 top/bottom/length/tilt 计算逐行对应 |
| `armor_detector/src/pnp_solver.cpp` | `src/pnp_solver.py::PnPSolver` | 模型点、图像点顺序、IPPE 一致 |
| `armor_tracker`（旋转目标 EKF） | `src/kalman.py`（平移 CV/CA KF）+ `src/gyro.py`（几何法陀螺估计） | 视频无 ROS 时钟，改为帧时间戳 n/150 s |
| `detector_node.cpp` 默认参数 | `src/detector.py` 参数类 | 默认值一致（light.min_ratio 0.1 等） |

视频模式新增（实拍视频与低曝光相机不同，必须处理）：
1. **颜色差分阈值**：原仓库直接灰度二值化（依赖低曝光相机）；普通视频背景亮，改用
   `R−max(G,B)` / `B−max(G,R)` + 灰度下限，对灯条颜色更鲁棒；
2. **灯条分段合并**：反光/遮挡把一条灯条断成几段，配对前先合并共线贴邻段；
3. **数字分类器(MLP)未移植**：本考核视频中测试台不含装甲板数字，用几何约束
   + 深度一致性检验 + 时间连续性替代（见 3.4）。

### 3.2 识别流程设计依据（问题①）

1. **颜色差分二值化**：灯条为高亮 LED，红/蓝通道显著高于其他通道；差分比单一通道
   或 HSV 更抗环境光色偏；
2. **轮廓 + minAreaRect**：灯条是细长亮条，旋转矩形给出长宽/倾角，计算量小、150 fps 可实时；
3. **灯条几何过滤**（短边/长边 ∈ [0.1, 0.4]、倾角 < 40°、面积下限）：排除大块发光板面、
   横条、噪点；
4. **两两配对**（两灯长度比 > 0.7、中心距/灯长 ∈ 小 [0.8,3.2] 或大 [3.2,5.5]、
   中心连线倾角 < 35°、包围盒内无第三灯条）：对应装甲板"两等长竖直灯条水平相邻"的
   几何先验；中心距/灯长同时给出小/大装甲板分类（小 135 mm、大 230 mm）。

### 3.3 误识别与错误配对的排除（问题②③）

- **画面中可能的误检物**：墙上的红色标识/光点、蓝色视频中机器人发光的板面（52×46 大块，
  长宽比 ≈ 0.9）、水平灯条（倾角 > 40°）、小噪点（面积下限）。以上均由灯条几何过滤排除。
- **相邻装甲板灯条错误配对**：测试台斜对相机时可同时看到两块板（4 根灯条），跨板配对
  会产生位于两板之间的假装甲板。处理：
  1. rm_vision 原生的"两灯条包围盒内存在第三灯条则放弃该配对"；
  2. **深度一致性检验**：PnP 深度 z 与"灯条像素长 → 55 mm → 深度"反算结果比较，
     相对差 > 22% 判为假配对剔除（跨板/错序配对过不了此检验）；
  3. **跟踪级 yaw 连续性门限**：候选与跟踪目标的 yaw 差 > 26° 拒绝关联，
     避免在轨道端点错误切到另一块板。
- **蓝色遮挡视频**：人员遮挡把灯条截断，将配对长度比下限放宽到 0.45、
  中心距下限放宽到 0.7 灯长，检出率从 12.6% 提升到 26%；遮挡导致单灯条可见的帧
  无法配对，属物理不可见，按"未识别"处理（评分按可见帧效果）。

### 3.4 位姿解算（问题④⑤）

- 相机参数来自 `camera_info.json`（fx=2319.9, fy=2322.7, cx=721.4, cy=606.3,
  畸变 k1=-0.0859, k2=1.065, p1=-0.0011, p2=-0.0016, k3=0），`cv2.solvePnP(..., IPPE)`。
- 坐标系：相机坐标系 x 右 / y 下 / z 前（m）；yaw = 板法向量在 x-z 平面的朝向角，
  正对相机为 0。
- **重要发现（数据检验结果）**：测试台同时装有**小装甲板（135 mm）与大装甲板（230 mm）**。
  判定依据：灯条 55 mm 反算的深度与板宽反算的深度在正确尺寸下自洽
  （如远距离平移视频：灯条 22 px → 5.8 m，板宽 90 px × 230 mm → 5.8 m 一致；
  若按 135 mm 则 3.5 m，与灯条深度矛盾 40%）。PnP 按配对结果自动选择小/大模型点，
  并用深度一致性检验复核，保证距离物理正确。
- **畸变系数影响实验**（远距离平移全部 1255 次检测）：使用/不使用畸变系数，
  z 相对差异均值 **0.17%**（最大 0.74%）；画面中心区域（|dx|<200 px）0.09%，
  边缘区域（|dx|≥400 px）0.30% —— 该 8 mm 镜头在目标所处画面区域畸变影响很小，
  且**越靠边缘影响越大**。
- **关键点顺序错误的后果**：CSV 顺序约定为 左灯条上端/左灯条下端/右灯条下端/右灯条上端
  （lt, lb, rb, rt）。若交换了左/右（如按 rt, rb, lb, lt），PnP 模型点与图像点不再对应，
  解出的 yaw 会翻转 ±180°（IPPE 还会给出镜像解），tvec 偏移；若上下颠倒则板法向翻转，
  深度可能解到错误方向。跟踪器按 yaw 连续性关联时会把翻转解当异常拒绝，
  造成漏跟——这正是数据中出现 yaw≈±180° 离群帧的原因。

### 3.5 运动预测（基本 3）

- **模型**：常速度（CV）线性卡尔曼滤波，状态 [x, vx, y, vy, z, vz]，dt = 1/150 s，
  Q 由连续白噪声加速度方差 q_acc 生成，R = diag(r²)。
- **0.25 s 预测**：更新后用状态转移矩阵前推 37 整步 + 1 半步（= 37.5 帧）。
- **观测处理**（问题⑥：噪声与异常）：
  1. 深度一致性检验剔除假配对；
  2. 关联门限：位置 0.4 m 且 yaw 差 < 26°；
  3. 速度幅值钳制（|v| ≤ 3 m/s）防止单帧坏值发散；
  4. 连续 20 帧无关联则判丢失并重初始化（对应轨道端点板切换/短暂漏检）。
- **结果**：1340 组"预测 vs 0.25 s 后实际观测"，**RMSE(3D) = 0.632 m，
  MAE(3D) = 0.443 m**（目标距离约 5.7 m，0.25 s 内移动约 0.4 m）。误差主要来自
  轨道端点往复换向（CV 模型在换向瞬间必然滞后）。

### 3.6 小陀螺目标估计（发挥 2，问题⑦）

- **关键观察**：相机只能看到正对自己的板，观测 yaw 呈**锯齿波**——在可见区间内
  以角速度 ω 线性扫过约 ±45°~±60°，换板时跳变约 90°。
- **角速度**：按 yaw 连续性把观测切成"扫掠段"，段内 yaw 对时间线性拟合，斜率即角速度；
  对各段斜率取加权中位数（权重 = 段长，剔除 |ω|<5 rad/s 的噪声/混板段）。
- **车体中心**：板绕中心对称分布，位置观测的**中位数**即中心（对 PnP 噪声鲁棒）。
- **结果**：

  | 视频 | 车体中心 (x, y, z) m | 旋转半径估计 | 角速度 ω |
  |---|---|---|---|
  | 中距离陀螺 | (−0.08, −0.25, 3.42) | ≈ 0.20 m | **−12.4 rad/s（约 −2.0 圈/s，俯视顺时针）** |
  | 近距离陀螺 | (0.03, −0.10, 2.34) | ≈ 0.11 m | **−23.3 rad/s（约 −3.7 圈/s，俯视顺时针）** |

  两段视频板切换跳变一致、段斜率同号（79% 以上段为负），角速度估计可信。
- **普通卡尔曼滤波器为何不适用于小陀螺目标（问题⑦）**：普通 CV/EKF 假设目标状态
  （位置、速度）平滑演化；而旋转目标的可观测板每 90° 切换一次，观测位置/朝向
  **周期性跳变**，且深度噪声（±0.3 m）远大于旋转半径（≈0.1~0.2 m），
  用位置序列估计旋转会在跳变点发散。rm_vision 的 armor_tracker 为此专门设计了
  旋转目标 EKF（状态含 yaw、r）。本项目用几何方法（yaw 分段斜率 + 位置中位数）
  更直观、更鲁棒地估计 ω 与中心。

### 3.7 Q、R 参数分析（发挥 3）

在远距离平移视频上以 0.25 s 预测 RMSE 为指标扫描：

| 配置 | RMSE(3D) m | 结论 |
|---|---|---|
| q_acc=0.2（Q 过小） | 0.78~0.84 | 滤波器过度信任模型，往复换向处明显滞后 |
| q_acc=16, r=0.01 | **0.685** | 最优区：Q 适中偏大、R 偏小 |
| q_acc=64, r=0.03 | 0.679 | 同上 |
| r=0.1（R 过大） | 0.70~0.83 | 过度平滑，预测跟不上快变 |
| CA 模型 (q_jerk=50, r=0.03) | 0.780 | 状态维数高、对参数更敏感，本数据不如 CV |

**结论**：① Q 决定滤波器对机动的信任度——目标往复机动时 Q 过小预测滞后严重，
Q 过大则预测抖动；② R 决定对观测噪声的抑制——本视频 PnP 噪声中等（R≈0.02 最优），
R 过大把真实运动也平滑掉；③ 预测误差随 Q 增大先降后稳，随 R 增大单调变差，
存在"Q 适中、R 偏小"的最优组合。配图见 `figures/QR分析_*.png`，数据见 `qr_analysis.csv`。

## 六、问题记录（供设计报告撰写参考）

1. **阈值失效**：最初用 rm_vision 原版灰度阈值 + 高亮度下限，蓝色视频几乎零检出——
   蓝灯灰度仅 ~77，被亮度下限误杀。改为高颜色差分阈值（90）+ 去掉亮度下限后恢复。
2. **轨道端点目标跳变**：远距离平移视频在轨道端点处另一块板进入视野，简单最近邻
   关联导致 KF 锁错目标、预测发散到 12 m。加 yaw 连续性门限 + 速度钳制 + 丢帧重初始化后
   RMSE(3D) 从 5.1 m 降到 0.63 m。
3. **陀螺视频位置信号失效**：PnP 深度噪声（±0.3 m）远大于旋转半径，位置圆周拟合
   完全失败（残差 0.55 m）；转向 yaw 锯齿波分段斜率估计后得到稳定结果。
4. **装甲板尺寸与题面不符**：题面称按小装甲板 135 mm 计算，实测深度自洽性检验证明
   测试台为大装甲板（230 mm，远距离视频主目标）且大小板混合，按实测尺寸解算。

## 七、AI 使用记录要点（供 ai_log.md 撰写参考）

本工程由 AI 辅助完成，关键交互示例：
1. **提问**："rm_vision 的 detector.cpp 如何移植为 Python 视频版？"
   —— AI 给出移植骨架，但**遗漏了视频模式所需的两处扩展**（颜色差分阈值、灯条分段合并），
   经实拍视频零检出/灯条断裂问题定位后自行补充。
2. **提问**："远距离平移 PnP 距离为何与灯条长度矛盾？" —— AI 最初建议沿用题面 135 mm，
   经深度自洽检验证明应为 230 mm 大板后修正（AI 未主动做该检验，是发现矛盾后补做的）。
3. **提问**："陀螺视频角速度如何估计？" —— AI 先建议位置圆拟合/FFT，两种方法均被
   数据噪声推翻（残差 0.55 m、频谱无显著峰）；最终采用 yaw 锯齿波分段斜率中位数，
   结果与板切换周期相互印证。
